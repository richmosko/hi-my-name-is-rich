# Keystatic CMS Integration

[Keystatic](https://keystatic.com/) provides browser-based content editing with live preview, frontmatter management, and image uploads -- all backed by Git commits.

## Why Keystatic

- **Git-backed** -- every edit is a GitHub commit, full version history
- **No database** -- reads/writes MDX files directly
- **Rich editor** -- WYSIWYG for markdown, typed fields for frontmatter (date pickers, dropdowns, tag arrays, image uploads)
- **Custom components** -- Gallery, YouTube, Video registered as insertable blocks
- **Two modes**: local (dev, reads filesystem) and GitHub (production, commits via GitHub API)
- **Draft support** -- branch-based drafts before merging to main
- **Built into Astro** -- first-class integration via `@keystatic/astro`

## Architecture

Keystatic is integrated directly into the Astro site using the official `@keystatic/astro` integration. There is no separate admin app -- the CMS admin UI lives at `/keystatic` on the same deployment.

```
Development (local mode):
  Astro dev server (port 4321)
  Admin UI at http://localhost:4321/keystatic
  Reads/writes MDX files on disk directly

Production (GitHub mode):
  Astro Node.js server (port 4321)
  Admin UI at https://himynameisrich.com/keystatic
  Authenticates via GitHub OAuth
  Commits changes to repo via GitHub API
  Coolify auto-deploys on push to main
```

### Key Files

| File | Purpose |
|------|---------|
| `keystatic.config.tsx` | Content schema -- collections, singletons, field definitions |
| `src/pages/keystatic/[...params].astro` | Renders the Keystatic admin UI (auto-generated by integration) |
| `src/pages/api/keystatic/[...params].ts` | Custom API route with reverse proxy URL fix |
| `src/components/KeystaticWrapper.tsx` | Re-exports Keystatic page component (Astro 6 compatibility) |
| `astro.config.mjs` | Registers `keystatic()` integration |

## Setup

### 1. Install Dependencies

```bash
npm install @keystatic/core @keystatic/astro
```

### 2. Register the Integration

In `astro.config.mjs`:

```js
import keystatic from '@keystatic/astro';

export default defineConfig({
  output: 'static',
  adapter: node({ mode: 'standalone' }),
  integrations: [
    // ... other integrations
    keystatic(),
  ],
});
```

The `output: 'static'` with `adapter: node({ mode: 'standalone' })` combination means most pages are pre-rendered at build time, but individual pages (like Keystatic routes) can opt into SSR with `export const prerender = false`.

### 3. Configure Content Schema

`keystatic.config.tsx` defines:

- **Collections**: `posts` and `projects` with typed fields matching MDX frontmatter
- **Singletons**: `authors` (manages `src/data/authors.json`) and `siteSettings` (manages `src/data/site-settings.json`)
- **Storage mode**: automatically switches between `local` (development) and `github` (production) based on `import.meta.env.PROD`
- **Custom MDX components**: YouTube, Gallery, Video blocks insertable from the editor toolbar
- **Custom marks**: big, underline, highlight, small text formatting

**Production detection:**

```tsx
const hasGitHubConfig = import.meta.env?.PROD ?? false;
```

Using `import.meta.env.PROD` (set by Vite/Astro at build time) instead of `process.env` which isn't available during the Astro build.

### 4. Astro 6 Compatibility Fix

Astro 6's React renderer doesn't match `.js` file extensions in production builds, which causes Keystatic's page component to fail with a "No valid renderer" error. The fix is `src/components/KeystaticWrapper.tsx`:

```tsx
export { default } from '@keystatic/astro/ui';
```

This re-exports the Keystatic UI component from a `.tsx` file that Astro's React renderer can match.

### 5. Reverse Proxy URL Fix

When running inside Docker behind Traefik (Coolify's reverse proxy), `request.url` returns `http://localhost:4321/...` instead of the public URL. This breaks GitHub OAuth callbacks.

The custom API route at `src/pages/api/keystatic/[...params].ts` rewrites the request URL using `X-Forwarded-Host` and `X-Forwarded-Proto` headers before passing to the Keystatic handler.

## GitHub App Setup (Production)

For GitHub mode, you need a GitHub App for OAuth authentication.

### 1. Create the GitHub App

1. Go to `https://github.com/settings/apps/new`
2. Fill in:
   - **GitHub App name**: `himynameisrich-keystatic` (must be globally unique)
   - **Homepage URL**: `https://himynameisrich.com`
   - **Callback URL**: `https://himynameisrich.com/api/keystatic/github/oauth/callback`
   - **Request user authorization (OAuth) during installation**: Checked
   - **Webhook**: Uncheck "Active" (not needed)
3. **Permissions** (Repository permissions):
   - **Contents**: Read & Write (for reading/writing MDX files)
   - **Pull requests**: Read & Write (for draft mode branch PRs)
4. **Where can this GitHub App be installed?**: Only on this account
5. Click **Create GitHub App**

### 2. Install the App on Your Repo

1. On the GitHub App settings page, click **Install App**
2. Select your GitHub account
3. Choose **Only select repositories** > `richmosko/hi-my-name-is-rich`
4. Click **Install**

### 3. Collect Credentials

After creating the app:

1. **Client ID** -- shown at the top of the app settings page
2. **Client Secret** -- click **Generate a new client secret** (copy immediately)
3. **App Slug** -- from the URL: `github.com/settings/apps/{this-is-the-slug}`
4. **Keystatic Secret** -- generate locally:
   ```bash
   openssl rand -hex 32
   ```

### 4. Set Environment Variables in Coolify

| Variable | Value | Type |
|----------|-------|------|
| `PUBLIC_KEYSTATIC_GITHUB_APP_SLUG` | The app slug from step 3 | **Build** |
| `KEYSTATIC_GITHUB_CLIENT_ID` | GitHub App Client ID | **Runtime** |
| `KEYSTATIC_GITHUB_CLIENT_SECRET` | GitHub App Client Secret | **Runtime** |
| `KEYSTATIC_SECRET` | The hex string from step 3 | **Runtime** |

- `PUBLIC_*` variables are inlined at build time (client-side)
- `KEYSTATIC_*` variables are server-side only (runtime)

### 5. Redeploy and Test

1. Redeploy in Coolify
2. Visit `https://himynameisrich.com/keystatic`
3. You should see a **Sign in with GitHub** button
4. Click it -- GitHub OAuth flow redirects you to authorize the app
5. After authenticating, you should see the admin UI with posts and projects listed
6. Try editing a post and saving -- it should create a commit on your GitHub repo
7. Coolify auto-deploys within ~1 minute

**Troubleshooting:**

- **Blank page**: Verify `KeystaticWrapper.tsx` exists and is properly referenced
- **OAuth redirect to localhost**: Check that `X-Forwarded-Host` headers are being passed by Traefik and that the custom API route at `src/pages/api/keystatic/[...params].ts` is deployed
- **"Missing required config" errors**: Verify all 4 environment variables are set in Coolify and redeploy
- **No posts visible**: Environment variables may not be reaching the build -- check Coolify build logs

## Content Editing Workflow

### Creating a New Post

1. Visit `https://himynameisrich.com/keystatic`
2. Click **Blog Posts > Create**
3. Fill in frontmatter fields:
   - Title (auto-generates slug)
   - Excerpt
   - Date (date picker)
   - Categories (multi-select dropdown)
   - Tags (dynamic array)
   - Featured (checkbox)
   - Hero Image (text path or upload)
   - Authors (multi-select)
4. Write content in the WYSIWYG editor
5. Insert custom components (YouTube, Gallery, Video) via the toolbar
6. Click **Save** -- commits to GitHub
7. Coolify auto-deploys within ~1 minute

### Editing Existing Posts

1. Visit `/keystatic`
2. Click **Blog Posts**
3. Browse or search for the post
4. Edit fields or content
5. Save -- commit -- auto-deploy

### Draft / Branch Workflow

The config uses `branchPrefix: 'keystatic/'`, which enables:

1. **Create a draft** -- save to a new branch (e.g., `keystatic/my-new-post`)
2. **Edit the draft** -- each save is a commit on that branch
3. **Preview** -- pull the branch locally and `npm run dev` to preview
4. **Publish** -- Keystatic creates a PR, merge to `main`, Coolify deploys

### Managing Authors and Site Settings

- **Authors**: Go to `/keystatic` > **Authors** singleton to add/edit author profiles (stored in `src/data/authors.json`)
- **Site Settings**: Go to `/keystatic` > **Site Settings** singleton to edit title, tagline, default images, admin links (stored in `src/data/site-settings.json`)
- **Categories**: Edit directly in `src/data/categories.ts` (not managed via Keystatic)

## Security

- Only GitHub users with **write access** to the repo can edit content
- OAuth tokens are scoped to the specific GitHub App
- The `KEYSTATIC_SECRET` encrypts session cookies
- No anonymous access -- authentication is required

## Decisions Log

| Decision | Choice | Rationale |
|----------|--------|-----------|
| CMS | Keystatic | Git-backed, no DB, rich editor, self-hosted, React-native |
| Integration | `@keystatic/astro` | First-class Astro integration; no separate admin app needed |
| Admin hosting | Same deployment at `/keystatic` | Single app, single deploy -- simpler than separate admin app |
| Production mode | GitHub mode via OAuth | Commits via GitHub API; no server filesystem writes |
| Content format | MDX | Already using MDX; Keystatic has native MDX field support |
| Draft support | Branch-based (`keystatic/` prefix) | Keeps `main` clean; PR workflow for publishing |
| Image handling | Text field (path) + image upload field | Text field for existing images, upload field for new ones |
| Auth | GitHub OAuth via GitHub App | Only repo collaborators can edit; no anonymous access |
